# Retro — 2026-08-31 · stage0b_v4_inventory

**Mode:** LOOPED. Plan approved, then run to the §7 stop condition. ~1 h wall, well inside
the 2–4 h estimate and the 8 h halt.

## What worked

- **Survey before planning.** Five minutes of `find` turned "1,087,490 files" into "7,746
  artifact rows" by applying the launcher's own extension list. The plan could then state a
  real scope instead of a guess, and the reviewer could see the reduction and check it.
- **Mechanical columns first, judgment columns last.** Round 1 filled everything derivable
  without judgment in 6 seconds. That left the expensive question — which artifact has a
  producing script — as the only thing needing care, and made the 72.2% `ABSENT` figure fall
  out of a script rather than an opinion.
- **Sampling my own output adversarially.** Re-checking 60 random script links against the
  file the evidence claimed caught nothing, which is the point: it converted "the script
  says 2,153" into "2,153, verified 60/60". Cheap, and the only reason I can state that
  number without hedging.
- **A lint for the rule that defines the stage.** The launcher forbids quality adjectives.
  A regex over the deliverables caught three of my own sentences, including one inside the
  disclaimer that said I would not assess quality. Writing the guard was faster than
  self-policing prose across 1,171 lines.

## What I got wrong

- **I let a section heading convict a file.** Marking an artifact `VOID` because the
  enclosing register section was titled "R18 — ⛔ S7 REFUTED" tagged 17 tables that are the
  *evidence for* the refutation, not the retracted object. The launcher's one rule is that a
  loop may drive but may not acquit — the symmetric half, that it may not *convict* either,
  is the half I nearly broke. Fix: a verdict is read only from the artifact's own line;
  heading proximity is recorded as an association with no verdict.
- **Then the narrowed rule was still wrong 3 times in 7.** The marker word on a line can
  govern a different object than the artifact on it — a column name, a value *inside* the
  file, or the artifact named as the *replacement* rather than the replaced. At n=7, reading
  all seven myself cost two minutes. **Lesson: when a heuristic's output is small enough to
  enumerate, enumerate it; a declared override table with the quoted line beats a cleverer
  regex.**
- **I wrote a mutation after the file write.** The override loop mutated `rows` *after* the
  `open(out, "w")` block, so three corrections printed to the console and never reached
  disk. The console said the right thing and the artifact was wrong — exactly the silent
  success `EVIDENCE_STANDARDS` §1 exists for. It was caught only because the finalizer
  re-counted from the written file instead of trusting the previous step's stdout.
  **Every stage boundary should re-derive its counts from the artifact, never inherit them.**
- **Two scripts stalled on quadratic patterns.** `[\w./-]+\.(?:py|sh|R)` backtracks
  catastrophically on long hex runs, and this corpus is full of them; an `endswith` scan over
  1.09 M paths was O(corpus) per token and, on inspection, unreachable. Both looked fine on a
  small input. On a corpus with million-file directories, assume the pathological input is
  present.

## What surprised me

**Zero `.prov.json` files exist in V4** — across 7,746 artifacts, 818 scripts, and four
months. The `has_prov_json` column is uniform and the `named_in_prov` evidence tier is
unreachable, so every script link in the table rests on a string occurrence instead. And
**392 of 400 figures have no script on disk that names them** — the artifacts a reader would
see first are the ones least attached to a way of regenerating them.

## For the next session

1. **Build the script index before the sweep, not after.** Round 1 opened every artifact for
   `claims_what` and Round 2 reopened many for `named_in_header`. One pass does both.
2. **A "does this file exist" check needs a scope.** The first version reported 786 missing
   paths; most existed in `MELISSA_DATA/` just outside the two inventory roots. Splitting
   `NOT_FOUND` from `OUTSIDE_INVENTORY_ROOTS` cut the real finding to 319 mentions and made
   it usable. Say where you looked before saying something is missing.
3. **Thousands separators are not just commas.** This corpus writes `31 030` as well as
   `31,030`; a comma-only pattern split the number and invented a value of `030` in a
   contradiction report. Numeric probes over prose need both separators.

## For WORKING_AGREEMENT.md, if it recurs

> and writes a file can disagree with itself. The count that goes in a report comes from
> reading the written file back, never from the producing step's stdout.
